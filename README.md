# SØLAR — магазин и панель управления

**Витрина онлайн:** https://kv9266855-sketch.github.io/solar-store/ — демо-режим на GitHub Pages: каталог, корзина, языки и темы работают; заказы, аккаунты, Нова Пошта и оплата monobank работают только при запуске Node-сервера (npm start).

Сайт на HTML/CSS/JavaScript с сервером Node.js и постоянной базой SQLite.
Вход, каталог, заказы, подписчики и настройки работают через сервер.

## Запуск

Нужен Node.js 24 или новее. Установка npm-пакетов не требуется.

Дважды нажмите Start-SOLAR.cmd либо выполните из папки проекта:

```powershell
npm start
```

Магазин: <http://127.0.0.1:8787/>. Админка: <http://127.0.0.1:8787/admin.html>.
Можно также войти через кнопку аккаунта в шапке и открыть панель управления.
Администратор — **Starkon**, пароль задан при настройке. Пароля в браузерном коде нет.
Открытие index.html без сервера и Python http.server больше не подходят.

## Что можно менять из админки

- Товары: добавление, редактирование, скрытие, удаление, цена, коллекция, размеры,
  остатки, цвета, описания и состав на четырёх языках, настоящие фотографии.
- Тексты: словари EN / UK / RU / FR, включая главную, About, Drops,
  доставку, возвраты, контакты, подписи кнопок и формы.
- Основатели: имена, фотографии и описания; фотография Starkon уже установлена.
- Главная: порядок и видимость блоков, свои текстовые блоки с фото и ссылкой.
- Страницы: дополнительные страницы с заголовком и текстом на четырёх языках.
- Навигация: меню шапки и подвала, ссылки, соцсети, контакты.
- Настройки: название бренда, год, SEO, заставка, объявление, оформление заказов,
  подписка, начальная тема.
- Дизайн: палитры светлой и тёмной тем, шрифты, дополнительный CSS.
- Медиа: загрузка фотографий с компьютера, библиотека и повторное использование.
- Заказы: список, детали, статусы, номер отправления и внутренние заметки.
- Клиенты и подписчики: данные из базы; экспорт и резервные копии контента.
- Полный JSON-редактор: все поля документа сайта, включая расширенные настройки.

Изменения содержимого применяются кнопкой сохранения. Они сохраняются в базе,
видны после обновления магазина и остаются после перезапуска сервера.
Если документ изменён в другом окне или заказом обновлены остатки, конфликт
сохранения сообщается явно — устаревшие данные не затирают новые.

## Аккаунты и заказы

Посетители могут зарегистрироваться, войти, изменить профиль и пароль,
просматривать собственные заказы. Управление сайтом доступно только администратору.
Пароли хранятся в виде хешей; сессии — в HttpOnly cookies.

Оформление заказа сохраняет заказ и уменьшает остатки. Стоимость и наличие
проверяются сервером, повторная отправка того же заказа не создаёт дубликат.
Оплата — **при получении**. Подписка сохраняет адрес в списке подписчиков.

Банковская онлайн-оплата, автоматическая отправка писем и оформление накладных
службы доставки требуют подключения соответствующих сервисов. Сайт не сообщает
об успешной оплате или отправленном письме, если этого не произошло.
Соцсети и контакты вводятся владельцем в настройках.
Изначальные товары отмечены как демо; их цены, фото, остатки и пометки меняются в админке.

## Доставка: Нова Пошта

При оформлении покупатель выбирает способ: Нова Пошта (отделение или почтомат),
курьер Новой Почты, Укрпочта или самовывоз. Для Новой Почты город ищется по
справочнику, затем показываются **все** отделения, почтоматы и грузовые отделения
этого города (поиск по номеру и улице, фильтры, подгрузка при прокрутке, метка
«примерочная»). Сервер сам обращается к API Новой Почты через /api/np/* и кэширует
список города на 12 часов, поэтому браузер не ходит к сторонним сервисам.
Выбранное отделение перепроверяется сервером при создании заказа.
Ключ API не обязателен; при необходимости укажите NP_API_KEY в окружении.

## Оплата картой: monobank (plata by mono)

Покупатель выбирает «Картой онлайн», сервер создаёт счёт в monobank и отправляет
покупателя на защищённую страницу оплаты monobank (карта, Apple Pay, Google Pay).
Данные карты магазин не видит и не хранит. После оплаты покупатель возвращается
на страницу #/payment/… со статусом заказа. Оплата при получении остаётся доступной.

Как включить:

1. Получите токен в кабинете monobank для бизнеса (раздел интернет-эквайринга).
   Для проверки можно взять тестовый токен — тогда платежи не настоящие.
2. Создайте в папке проекта файл .env (образец — .env.example) и впишите:

   MONO_TOKEN=ваш_токен
   SOLAR_PUBLIC_URL=https://ваш-домен

3. Перезапустите сервер (Start-SOLAR.cmd или npm start). Сервер читает .env сам.
4. В админке → Настройки → «Оплата картой онлайн» можно временно выключить оплату картой.

Без MONO_TOKEN вариант «Картой онлайн» на сайте не показывается.
SOLAR_PUBLIC_URL нужен для мгновенных уведомлений monobank (вебхук
/api/payments/monobank/webhook, подпись проверяется открытым ключом monobank).
Пока сайт работает только на компьютере, статус оплаты проверяется, когда покупатель
возвращается со страницы оплаты, и кнопкой «Проверить оплату» в карточке заказа.

Что видно в админке: статус оплаты в списке заказов, дата оплаты, номер счёта,
кнопки «Проверить оплату» и «Вернуть деньги» (полный возврат на карту покупателя).
Оплаченный заказ покупатель не может отменить сам — только через магазин.
Неоплаченный заказ с картой держит товар в резерве; если покупатель так и не оплатил,
отмените заказ в админке, и товар вернётся на склад. В кабинете у такого заказа есть
кнопка «Оплатить».

Фискальные чеки (ПРРО) при онлайн-оплате подключаются в кабинете monobank —
уточните у бухгалтера, нужны ли они вашему ФОП.

## Кабинет покупателя (#/account)

Заказы со статусом, шкалой выполнения, историей и номером ТТН; живой статус
посылки Новой Почты; отмена заказа, пока он новый (товар возвращается на склад);
«заказать ещё раз»; профиль, сохранённый адрес доставки (подставляется при
оформлении) и смена пароля.

## Панель управления

Обзор: выручка (завершённые / в работе), средний чек, заказы за день, график
выручки за 30 дней, статусы, хиты продаж, города и способы доставки, размеры,
которые заканчиваются. Заказы: фильтры по статусу, поиск по ТТН и городу,
карточка с историей, кнопкой следующего шага, копированием данных для накладной
и проверкой статуса ТТН. Покупатели: число заказов, сумма покупок, адрес доставки.

## Шрифты

Unbounded (заголовки), Manrope (интерфейс), Cormorant Garamond (редакционные
акценты) — локальные woff2 с кириллицей, латиницей и знаком ₴ (лицензия SIL OFL),
подключены через css/fonts.css. Названия шрифтов можно сменить в админке → Оформление.

## Данные и копии

data/solar.sqlite — аккаунты, сессии, сайт, заказы и подписчики.
data/uploads/ — загруженные фотографии. Изображения выдаются сервером
через отдельный маршрут /uploads/. Не удаляйте папку data: это рабочие данные магазина.

Полная копия сайта с базой, загруженными файлами и исходниками:

```powershell
npm run backup
```

Копия появляется в _backup/full-…/. Для переноса остановите сервер и перенесите
приложение вместе с папкой data, затем запустите npm start.
JSON-экспорт в админке удобен для переноса настроек и контента; полная копия
через команду также включает аккаунты и сами файлы фотографий.

_backup/v1-minimal/ — исходный минималистичный вариант.
_backup/v2-photo-bg/ — вариант с фотофоном.
_backup/v3-before-codex/ — файлы перед исправлением тем.
_backup/v4-before-admin/ — магазин до добавления сервера и админки.

## Настройка сервера

По умолчанию HOST=127.0.0.1, PORT=8787. Другую папку данных можно указать через
переменную SOLAR_DATA_DIR. Для хостинга нужен постоянно работающий Node.js 24+
и постоянный диск; простой статический хостинг не подходит.
За HTTPS-прокси включите SOLAR_SECURE_COOKIE=1.

Для создания администратора в новой базе задайте SOLAR_ADMIN_PASSWORD
в окружении процесса и выполните npm run setup-admin. Существующая учётная запись
не должна сбрасываться при обычном запуске сервера. Менять свой пароль можно в аккаунте.

## Проверка

```powershell
npm run check
npm test
```

Проверки охватывают синтаксис, локальные ресурсы и серверные сценарии:
права доступа, CSRF, вход, сохранение контента, цены/остатки заказов и приватность данных.
